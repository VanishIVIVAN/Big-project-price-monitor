# Ціни на електроніку: моніторинг магазинів зі сповіщеннями

Сайт на Python (Flask). Користувач обирає категорію електроніки (ноутбуки, смартфони, планшети, монітори, навушники, смарт-годинники, телевізори), вводить назву, фільтрує результати, відкриває модель і бачить:

- список магазинів, де вона продається, з актуальними цінами, старою ціною та знижкою;
- графік цін по кожному магазину (чорно-білий, магазини відрізняються стилем лінії та маркером);
- кнопку «Додати в бажане»: коли в якомусь магазині ціна впаде, приходить сповіщення на сайті (і на пошту, якщо вона вказана та налаштований SMTP).

**Тема завдання:** моніторинг інтернет-магазинів електроніки та цін зі сповіщеннями (власна тема).

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run.py                    # http://127.0.0.1:5000
```

Корисні команди:

| Команда | Що робить |
|---|---|
| `python run.py check-stores lenovo` | запитує кожен увімкнений магазин і показує, скільки товарів знайдено або яка помилка |
| `DEMO_MODE=1 python run.py` | працює з вигаданими магазинами (ціни змінюються щохвилини), щоб перевірити весь сценарій без інтернету |
| `python run.py refresh` | один раз оновлює ціни всіх товарів зі списків бажаного |
| `python -m unittest discover -s tests -v` | тести |

Налаштування через змінні оточення: `SECRET_KEY`, `DATABASE_PATH`, `ENABLED_STORES` (наприклад `comfy,moyo,foxtrot,epicentr`), `MONITOR_INTERVAL_MINUTES` (за замовчуванням 360), `MIN_DROP_PERCENT` (мінімальне падіння ціни для сповіщення, за замовчуванням 1), `REQUEST_TIMEOUT`, `DEMO_MODE=1`, для пошти: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`.

## Магазини

Перед написанням коду я перевірив, чи віддають магазини ціни в HTML, який можна прочитати програмою.

| Магазин | Статус | Результат перевірки |
|---|---|---|
| Comfy | увімкнено | сторінка каталогу завантажилась, є назви, коди товарів, старі та нові ціни |
| Moyo | увімкнено | те саме; код моделі виробника є в назві |
| Foxtrot | увімкнено | сторінка завантажилась, таблиця цін є в HTML; повний список товарів я не підтвердив |
| Епіцентр | увімкнено, **додано замість недоступних** | сторінка каталогу завантажилась із цінами, старими цінами та наявністю |
| Rozetka | вимкнено | мій запит було заблоковано захистом від ботів |
| Цитрус | вимкнено | сторінок магазину я не знайшов і перевірити не зміг |
| Prom | вимкнено | не перевірено; це маркетплейс з багатьма продавцями та сильним захистом від ботів |

З шести заданих магазинів надійно підтверджено лише половину, тому додано Епіцентр. Вимкнені магазини можна спробувати увімкнути: `ENABLED_STORES=comfy,moyo,foxtrot,epicentr,rozetka`. Якщо магазин блокує запити, сайт не ламається: на сторінці пошуку показується, який магазин недоступний і чому.

**Важливо.** Перевірку я робив із середовища без доступу до вашої мережі, тому:

- адреси пошуку магазинів (`search_url` у `app/stores.py`) складені за звичайними схемами сайтів і не перевірені наживо;
- парсер не залежить від CSS-класів, але його тести використовують невеликі власноруч написані фрагменти HTML, схожі на структуру каталогів, а не копії справжніх сторінок.

Тому перший крок після запуску: `python run.py check-stores lenovo`. Якщо магазин повертає 0 товарів, поправте `search_url` або шаблон посилань `product_path` для нього в `STORE_SPECS`.

## Як це працює

- **Пошук.** Запит іде в усі магазини паралельно. Аксесуари відкидаються (чохли, сумки, кабелі тощо). Однакові моделі з різних магазинів об'єднуються за кодом виробника в дужках, наприклад `(82XQ01K9RA)`; якщо коду немає, за набором слів назви.
- **Фільтри.** Бренд, діапазон цін, «лише в наявності» та характеристики через кому (`16 гб, oled`). Характеристики шукаються в назві та в короткому описі з картки товару, тож працюють лише для тих параметрів, які магазин показує у списку.
- **Історія цін.** Магазини не віддають історію, тому вона накопичується з першого перегляду: при кожному пошуку, оновленні та фоновій перевірці. Фонова перевірка товарів із бажаного йде раз на 6 годин.
- **Сповіщення.** Коли ціна в магазині впала щонайменше на `MIN_DROP_PERCENT` % порівняно з попереднім записом, усі, хто має товар у бажаному, отримують повідомлення.

## Структура та ООП-дизайн

```
app/
  config.py         налаштування з оточення
  domain.py         модель даних (Offer, Product...), нормалізація назв
  storage.py        SQLite: користувачі, товари, ціни, бажане, сповіщення
  stores.py         Store (інтерфейс) -> HtmlCardStore, DemoStore; StoreSpec на кожен магазин
  notifications.py  Notifier (інтерфейс) -> InAppNotifier, EmailNotifier, CompositeNotifier
  services.py       SearchService, PriceTracker, PriceMonitor
  charts.py         чорно-білий SVG-графік
  views.py          маршрути Flask, templates/ і static/ вигляд
run.py              запуск і діагностика
tests/              тести
```

Сервіси працюють лише з інтерфейсами `Store` і `Notifier`, тому новий магазин або канал сповіщень (Telegram тощо) додається без змін решти коду. Один загальний парсер налаштовується описом `StoreSpec`, без окремого коду на кожен магазин.

## Виконання загальних вимог

- ОО-дизайн, поділ на модулі, відсутність дублювання: див. вище.
- Одна програма з однією точкою входу (`run.py`).
- Обробка помилок: недоступні та заблоковані магазини, збої мережі, некоректні фільтри та запити, дубльовані користувачі, помилки пошти, неправильна конфігурація. Усе це покрито тестами (`tests/`).
- Стиль коду: [PEP 8](https://peps.python.org/pep-0008/), анотації типів, докстрінги.
- Source control: git, коміти за етапами розробки.
- Додаткових (необов'язкових) вимог не реалізовано.

## Обмеження

- Об'єднання моделей за кодом виробника: деякі магазини (наприклад, у смартфонів Apple) пишуть різні регіональні коди, тоді одна модель може показатися двома.
- Структура сторінок магазинів змінюється; парсер потрібно підтримувати.
- Паролі зберігаються хешованими; для публікації в інтернеті потрібні HTTPS, випадковий `SECRET_KEY` і справжній WSGI-сервер замість `python run.py`.
